# Chapter 3 — Documentation

Detailed developer documentation for the Chapter 3 code samples ("Prompt
Engineering: The New Enterprise Interface"). Complements the short `README.md` with
setup, per-file walkthroughs, expected output, and the reasoning-model notes.

---

## 1. What this chapter teaches

Chapter 3 treats prompts as **engineered, versioned, governed artifacts** rather
than throwaway strings:

1. **Prompts as templates** — declared variables, render-time validation, a durable
   system / per-request user split (`prompt_template.py`).
2. **Techniques are measurable** — zero-shot vs. few-shot vs. chain-of-thought on a
   boundary-heavy eval set (`technique_lab.py`).
3. **Prompt governance rides Git** — a file-based registry with model pin, owner,
   eval evidence, and approvals (`prompt_registry.py`).

## 4. Files in this chapter

| File | Book section | Purpose |
|---|---|---|
| `prompt_template.py` | 3.11.1 | Minimal template engine: declared variables, render-time validation, system/user split. |
| `technique_lab.py` | 3.11.2 | Zero-shot vs. few-shot vs. chain-of-thought, measured on a boundary-heavy eval set. |
| `prompt_registry.py` | 3.11.3 | File-based prompt registry with governance metadata. |
| `registry/` | 3.11.3 | Sample registry artifacts (generated by `prompt_registry.py`; committed to Git). |

### 4.1 `prompt_template.py`
Defines a frozen `PromptTemplate` dataclass. `variables` parses `{{name}}` tokens;
`render(**values)` fails loudly on missing or unexpected variables, then returns the
filled `(system, user)` pair. Running it renders the Meridian returns template and
drafts one email via Anthropic.

### 4.2 `technique_lab.py`
Runs three prompting techniques against six deliberately fuzzy supplier emails and
reports accuracy, output tokens, and latency per technique. Misses are printed so
you can see *where* each technique wins or loses.

### 4.3 `prompt_registry.py`
`save(...)` writes a template plus governance metadata (model pin, owner, eval
evidence, approvals) to `registry/<name>/<version>.json`; `load(name, version)`
reads it back. No floating "latest" — versions are pinned. **Commit `registry/`** —
prompt governance then rides the same Git rails (diff, blame, review, rollback) as
your code.

## 5. Reasoning-model changes

Consistent with ch01–ch02, the current flagship models (`gpt-5.5`,
`claude-sonnet-5`) are reasoning models. Two adjustments were made here:

1. **`temperature` removed.** `prompt_template.py` passed `temperature=0.4` and
   `technique_lab.py` passed `temperature=0.0`; neither is accepted anymore, and the
   ch01 wrapper no longer forwards it. The arguments were removed to avoid implying
   an effect that does not happen.
2. **Token cap raised.** `technique_lab.py` went from `max_tokens=200` to `512` so
   the chain-of-thought variant (which also emits reasoning) is not truncated.
   `prompt_template.py` runs fine on the default 500-token budget.

Conceptual caveat for `technique_lab.py`: because the models now reason internally,
explicit chain-of-thought prompting overlaps with what the model already does, so
the three variants may converge more than the book's original text describes. The
core lesson still holds — see the observed run below, where few-shot pins the
boundary case that zero-shot misses.

## 6. How to run

```bash
python prompt_template.py    # renders the template + drafts one email
python technique_lab.py      # three-variant comparison (18 OpenAI calls; minutes)
python prompt_registry.py    # writes and reloads a registry artifact
```

### Observed output (shape; exact values vary)

`prompt_template.py` prints the rendered SYSTEM and USER blocks, then a DRAFT email,
e.g. `--- DRAFT (273+286 tokens) ---`.

`technique_lab.py`:

```
  MISS [zero-shot]: expected 'escalation' ← 'Third reminder: INV-4402. ...'
zero-shot          5/6 correct    304 output tokens    23.2s
few-shot           6/6 correct    240 output tokens    10.2s
  MISS [chain-of-thought]: expected 'escalation' ← 'Third reminder: INV-4402. ...'
chain-of-thought   5/6 correct    809 output tokens    19.2s
```

`prompt_registry.py`:

```
Registered: .../registry/returns/status-email/1.0.0.json
Loaded returns/status-email@1.0.0 with variables [...]
```

> `technique_lab.py` makes 18 reasoning-model calls and can take several minutes.

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: ai_client` | ch01 not importable | Set `PYTHONPATH=../ch01` or copy `ai_client.py` here. |
| `UnicodeEncodeError` | Windows cp1252 console | `$env:PYTHONUTF8="1"`. |
| Empty / truncated answers | Token cap too low for a reasoning model | Raise `max_tokens` (already applied to `technique_lab.py`). |
| `ValueError: ... missing [...]` / `unexpected [...]` | Template variable mismatch | Pass exactly the variables the template declares (this is the intended safety check). |
