# Chapter 3 — Prompt Engineering: The New Enterprise Interface

Code for sections 3.10–3.11 of the book.

| File | Book section | Purpose |
|---|---|---|
| `prompt_template.py` | 3.11.1 | Minimal template engine: declared variables, render-time validation, system/user split |
| `technique_lab.py` | 3.11.2 | Zero-shot vs few-shot vs chain-of-thought, measured on a boundary-heavy eval set |
| `prompt_registry.py` | 3.11.3 | File-based prompt registry with governance metadata (model pin, owner, evidence, approvals) |
| `registry/` | 3.11.3 | Sample registry artifacts (generated by `prompt_registry.py`) |

`prompt_lint.py` (the Cursor exercise in section 3.12) is left for the reader; a reference solution may be added under `solutions/`.

## Setup

These scripts import `ai_client` from `../ch01`:

```bash
cd ch03
cp ../ch01/.env .
cp ../ch01/ai_client.py .    # or export PYTHONPATH=../ch01

python prompt_template.py    # renders the Meridian returns template + drafts one email
python technique_lab.py      # runs the three-variant comparison (uses OpenAI)
python prompt_registry.py    # writes and reloads a registry artifact
```

Commit the `registry/` directory: the whole point is that prompt governance rides Git.

Models used at time of writing: `gpt-5.5`, `claude-sonnet-5`. All company names, people, and URLs in the templates are fictional.
